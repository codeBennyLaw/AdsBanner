# AdsBanner

Android 端的开屏广告跳过与误触跳转拦截工具。

通过无障碍服务识别其他应用开屏页上的「跳过」按钮并自动点击；当你误触广告、被强行拉起淘宝、京东这类购物应用时，立即退回原来的应用。拦截次数按应用统计，可以在应用内查看。

全程离线运行，不申请网络权限，数据只保存在本机。

## 功能

- **开屏广告跳过**：进入应用后自动识别并点击「跳过 / 关闭广告」按钮，文案匹配结合屏幕位置判断，减少误点
- **误触跳转拦截**：在别的应用里误触广告被拉起购物类应用时，立即返回原应用
- **拦截名单**：拦截目标可自行勾选，默认包含主流电商、短视频和浏览器
- **按应用统计**：分别记录开屏与跳转的今日、累计次数，支持按类型筛选与清空
- **后台存活**：常驻通知提升进程优先级，开机后自动恢复

## 工作原理

两条能力各自独立：

1. **开屏跳过**：应用切到前台后，在 10 秒窗口内遍历其可访问性节点树，找出文案命中规则且位置合理的「跳过」类控件并点击。文案分强、弱两级 —— 强匹配（跳过、关闭广告、skip）允许在顶部区域点击，弱匹配（关闭、×）只在右上角点击，避免关掉正常弹窗。

2. **跳转拦截**：广告跳转的可靠特征是「用户还在 A 应用里，A 应用突然把 B 应用切到前台」。因此记录上一次前后台切换的时间，若快速切到名单内的应用、且来源不是桌面或系统界面，判定为被强行拉起，延迟后发送返回。

## 权限与限制

需要在系统设置中手动开启无障碍服务，应用无法自行授权：

| 权限 | 用途 |
| --- | --- |
| 无障碍服务 | 读取其他应用界面节点、模拟点击与返回 |
| 通知权限 | Android 13+ 显示常驻通知 |
| 开机自启 | 重启后恢复守护 |
| 电池优化白名单 | 避免休眠时服务被断开 |

系统层面的限制：

- 没有任何 API 能在点击落地前拦截 Intent 跳转，无障碍服务只能观察和模拟操作。因此跳转拦截一定是「先跳过去、再立刻退回来」，会有一帧闪现
- 摇一摇触发的跳转无法阻止，只能等它跳完再返回
- 用户主动点击淘宝链接同样会被判定为误触，需要到名单里去掉对应应用
- 开屏广告若在 WebView 或自绘 Surface 中渲染，节点树拿不到内容，无法识别
- Android 14 起，非应用商店渠道安装的应用，无障碍开关会落在「受限设置」中，需要在应用信息页点「允许受限设置」
- 被手动「强行停止」后所有服务失效，需重新打开应用

## 使用

1. 安装后打开 AdsBanner，点「去开启」进入系统无障碍设置，开启「AdsBanner · 广告拦截服务」
2. 回到应用，状态显示为运行中即生效
3. 按需到「跳转拦截名单」调整要拦截的应用
4. 如需在清理后台后保持存活，点「加入电池优化白名单」，并参照应用内的国产 ROM 指引放行自启动与后台运行

## 构建

需要 JDK 17 与 Android SDK（compileSdk 35）：

```bash
./gradlew assembleDebug
./gradlew assembleRelease
```

产物位于 `app/build/outputs/apk/`，文件名形如：

```
AdsBanner-debug-v-1-0-0.apk
AdsBanner-release-v-1-0-0.apk
```

Release 使用本机 debug keystore 签名，可直接安装；覆盖安装时新旧包签名需一致。

## 项目结构

```
app/src/main/java/com/adsbanner/clean/
├── core/          配置、统计存储、跳过规则、应用信息缓存
├── service/       无障碍服务、前台常驻服务
├── receiver/      开机广播
└── ui/            主界面、统计页、拦截名单
```

## 说明

本项目仅供学习交流使用。广告拦截依赖各应用自身的界面结构，应用更新后可能需要调整识别规则。
