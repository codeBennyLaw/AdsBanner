# 3.1.3 开屏兼容性、响应与成功记录修复

## 反馈与修复范围

用户先反馈学习通右下角「跳过2s」没有被跳过，安装修复包后确认跳过、统计与 LiveUpdate 正常，随后反馈关闭偏慢、哔哩哔哩漏跳。本次没有连接用户设备，未读取这两个应用当前版本的真实节点；以公开控件规则和独立模拟页面核对兼容路径。

最终规则分别使用应用专属开屏证据与通用倒计时证据：

- 哔哩哔哩及 HD 包按各自的完整 `count_down`、`skip` ID 查询，兼容「跳过」、角落里的纯数字或空文字控件。页面必须已声明且目标属于该已确认窗口；首帧身份未确认、搜索与设置 Activity 均不能借用这些 ID。学习通独立 SplashActivity 与哔哩哔哩专属开屏 Activity 的小型角落按钮可直接提供开屏证据，无需再等倒计时变化。
- 其他缺少可访问点击动作的紧凑控件，需要完整的 1～10 秒跳过倒计时、稳定位置和安全节点层级；在有限的启动或恢复检测窗口内参与。顶部和右下角优先，广告留白造成控件上移时仍可处理；宽度不超过屏幕的 32%，高度不超过 8%。
- 通用倒计时路径要求同一窗口、稳定位置的倒计时实际减少，间隔在 250～3000ms 内；只有短暂有效的变化证据可授权点击。静态「跳过2s」说明文字、倒计时增加、控件换位等情况不能提供证据。
- 搜索栏、设置用途、开关、输入框和冲突父控件被排除。通用触摸控件不能借用滚动或分页祖先；应用专属开屏控件可以位于滚动内容上方，但滚动容器本身不能作为目标。大广告父容器不接收点击，坐标始终取目标自身中心，并重新核对实际前台与窗口遮挡。
- 进入应用、切换已声明 Activity 或确认活动窗口变化后，坐标触摸至少等 350ms 再核对目标，避免无障碍已报告最终坐标、窗口入场动画尚未结束时点到背景。旧窗口晚到的普通 View 事件不重新延长等待；原生节点动作不因这项检查延迟。
- 无点击动作的控件在同一窗口、位置，本次启动最多接受一次坐标手势。倒计时节点重建、数字或文案变化不重新分配尝试次数；控件持续消失后才记录成功。

遮挡和屏幕配置变化清理未确认的倒计时证据，同时保留已经消耗的手势次数。普通点击与长按停止扫描；哔哩哔哩列表滚动时，将检测收窄到应用专属开屏 ID，避免自动恢复列表位置提前结束开屏检测。返回其 MainActivity 可开启有限的专属 ID 检测，进入已声明的独立开屏页可开启强匹配检测；普通页面返回不重开通用文字扫描。未确认的倒计时只开启最多 1.5 秒的快速轮询，静态文字不使整个检测期持续高速扫描。

## 回归方式

使用本地 Android 16 / API 36 模拟器，对照 3.1.2 已发布包与 3.1.3 的 Release 构建包。独立模拟应用提供右下角、右上角、描述中拆分文案及每秒重建节点的触摸按钮；背景和按钮分别记录点击，探针核对 AdsBanner 的成功统计。

初次回归复用 3.1.2 的普通入口、说明文字、开关、引导页、广告设置、远处广告标记、返回循环、成功后再次返回及用户主动操作用例。补充静态倒计时、位置变化、倒计时增加、中部控件、大控件、冲突父节点、滚动容器与持续无效触摸控件。最终兼容性回归将中部真实递减的紧凑倒计时改为正例，静态与错误动作反例仍要求不点击。

3.1.2 与首次 3.1.3 修复包分别通过 86 项模拟器断言：前者没有点击四类无点击动作的倒计时目标，后者均关闭一次、统计一次；普通页面反例没有误点。持续无效的目标仅收到一次手势，未计为成功。补充了即使暂时报告不可滚动，也按类型排除滚动与分页祖先容器的校验。当时 189 项单元测试通过，Debug、Release 构建完成。

原始模拟页面、探针和对照结果保存于忽略目录 `app/build/ui-review/splash-313`，不随应用发布。本次结果覆盖模拟的无点击动作倒计时控件；尚未完成学习通当前版本的实体设备回归。

## 成功确认、统计与实时通知补充

用户确认新版 Debug 能跳过学习通开屏，随后反馈没有统计加一和 LiveUpdate。旧确认流程会把手势产生的大父容器点击回报当作用户操作撤销等待，也会在控件晚于 180ms 消失时过早判为失败；主页的自动滚动事件同样可能清空已经消失的目标。

补充修复将停止新扫描与完成已提交动作的结果确认分开。实际前台仍是原应用且系统未遮挡时，若原目标与替代目标已消失，或窗口已切换但新 Activity 事件尚未到达，则取消后续扫描、短暂保留这次结果确认；该确认不继续发出点击，也不直接计数。父容器回报匹配原窗口、包含原目标并落在手势开始后的 300ms 内时，视为自身手势回报。退出动画暂缺根节点或窗口描述时，同一应用、同一有效窗口在这 300ms 内的点击事件只能保留已提交手势的结果确认；新扫描仍停止，成功仍须随后核对前台、遮挡和控件持续消失。页面身份按包名与窗口 ID 保存，普通 View 类名及旧窗口晚到事件不覆盖当前窗口的身份。

手势结束后允许最多 1 秒等待控件关闭与页面切换，并继续要求目标持续消失 200ms。窗口 ID 改变本身不算成功：只有确认进入另一已声明 Activity 且原窗口不再可见，才能排除旧窗口残留的可见节点；弹窗遮挡原广告不会计数。最终成功仍统一调用一次统计记录和实时通知入口。

模拟对照补充父容器点击回报、回报后立即切页、延迟 450ms 关闭、主页自动滚动、跨 Activity 关闭，以及持续无效控件和遮挡弹窗。探针同时检查实际点击、成功计数、实时通知数量及通知的 Live Update 格式资格。该模拟器的 `canPostPromotedNotifications()` 返回 false，因此没有实际提升标志；结果验证的是通知发送及可提升格式，不把“已提升”作为软件发送成功的断言。原始结果位于 `app/build/ui-review/splash-result-313`。

结果确认专项共 27 项断言通过。旧包中父容器回报、回报后切页、延迟关闭与主页自动滚动四类场景均已点击成功但未计数、未创建实时通知；修复包均记录一次并生成一条合格通知。持续无效控件与遮挡弹窗均不计数。补充后 196 项单元测试及原有 86 项触摸与误点保护回归均通过，Debug、Release APK 已重新构建。

## 哔哩哔哩兼容与响应回归

公开订阅的[哔哩哔哩开屏规则](https://github.com/Lin-arm/GKD_subscription/blob/aa10e7f361c3dcb8f123cc768d2adb35406b1a6d/src/apps/tv.danmaku.bili.ts)按 `count_down` 与 `skip` ID 匹配，注释指出仅按「跳过」文字可能误点搜索内容；[学习通规则](https://github.com/Lin-arm/GKD_subscription/blob/aa10e7f361c3dcb8f123cc768d2adb35406b1a6d/src/apps/com.chaoxing.mobile.ts)限定独立 SplashActivity，并通过文字子节点定位可点击父控件。这里只据此核对控件身份与页面范围，没有将外部订阅或快照当作本次真机结果。

独立模拟应用使用这两个应用的包名、完整资源 ID 与 Activity 名称，核对纯文字、纯数字、空文字、无点击动作、较大点击父控件、滚动祖先、部分可见按钮与窗口入场动画。补充从其他页面进入独立开屏、返回主页后出现专属控件，以及返回后只有普通搜索文字的用例。反例涵盖未识别 ID、搜索栏及其子节点、开关、输入框、视频跳过片头、过大目标、完全移出屏幕的控件和设置 Activity。

回归还要求冷启动继续检查通用真实倒计时，首个 Activity 声明不能被当作返回主页而提前收窄规则。探针分别核对实际关闭、尝试次数、背景点击、统计增量、实时通知和显示到点击的耗时；独立开屏切页用例等待退场动画与成功确认完成后再读取结果。原始页面、探针、事件追踪和结果保存在忽略目录 `app/build/ui-review/bili-313`。

新包通过 101 项专项断言，旧包通过 79 项对应基线断言。新包中的可关闭专属开屏控件均关闭一次、统计一次、生成一条实时通知，显示到点击为 133～686ms；旧包中未提供完整跳过倒计时的哔哩哔哩专属控件没有被点击。学习通模拟控件设定首次倒计时变化在创建后 2 秒发生，旧包点击耗时 1875ms，新包为 543ms；这组对照证明新路径无需再等待数值变化。通用真实倒计时仍须观察变化，旧包为 906ms，新包为 896ms。静态、错误动作、搜索和设置反例没有点击或成功记录，持续无效的触摸目标只收到一次手势。

快速匹配也会刷新候选节点，避免初始坐标停留在窗口入场前的位置；晚到的后台 View 窗口事件先核对实际活动应用，不能覆盖前台身份。活动根节点已返回 AdsBanner 时，同步结束旧应用的检测和前台记录，避免接下来的同应用冷启动沿用已经结束的状态。广告按钮的标签容器不因通用标题样式而排除，搜索、输入和开关层级继续校验。

最后的结果确认回归还复现了父容器回报后立即切页时的窗口缓存问题。等待确认原控件消失期间，同样处理窗口缓存失效；活动应用窗口与缓存根不一致时读取该活动窗口的根，确认进入另一已声明 Activity 后重新读取窗口列表，避免旧窗口缓存阻止计数。同窗口的短暂手势回报在查询根和遮挡之前只保留有限确认，不能因此计数。完整结果专项的 27 项断言通过，包含父容器回报与立即切页、延迟关闭、自动滚动、持续无效触摸和弹窗遮挡。

最终源码通过 212 项单元测试、101 项兼容专项、86 项触摸与误点保护断言，以及 27 项结果确认与实时通知断言；Debug 与 Release 构建完成。

本次首次连续兼容回归中，持续无效触摸控件漏掉了预期的一次尝试，实际点击与统计均为 0。同一源码的独立用例和随后未启用事件追踪的完整 101 项回归均通过；暂未定位这次漏尝试，继续保留为启动时序观察项。

这些结果覆盖独立模拟控件，尚未验证哔哩哔哩和学习通当前版本 APK 的真实节点；HD 包只完成资源命名空间的单元验证。模拟器没有实际提升通知的系统资格，LiveUpdate 回归核对通知发送与可提升格式。
