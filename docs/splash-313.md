# 3.1.3 倒计时触摸控件漏跳修复

## 反馈与修复范围

用户反馈学习通的开屏没有被跳过，截图右下角显示小型白色「跳过2s」控件。该文案已在现有完整匹配规则内，3.1.2 对可访问点击动作的要求则会排除只响应触摸的控件。本次未连接用户设备、未读取学习通实际节点，以相同位置和文字的模拟控件验证这一漏跳路径。

通用规则继续区分普通页面文字与真正跳过控件。对没有自身或紧贴父节点点击动作的目标，新增受限的坐标兜底：

- 只在当前应用原启动检测窗口内参与，用户操作后、恢复检测和系统遮挡期间不参与。
- 目标必须是右上角或右下角的小型控件，完整文案包含 1～10 秒的跳过倒计时；设置、开关、摘要等节点 ID 不参与。
- 同一窗口、稳定位置的倒计时必须实际减少，间隔在 250～3000ms 内；只有短暂有效的变化证据可授权点击。静态「跳过2s」说明文字、倒计时增加、控件换位等情况不能提供证据。
- 开关、输入框、滚动容器和紧贴父控件的冲突动作继续被排除；大广告父容器不接收点击，坐标始终取目标自身中心，并重新核对实际前台与窗口遮挡。
- 同一窗口、位置的控件，本次启动最多接受一次坐标手势。倒计时节点重建、数字或文案变化不重新分配尝试次数；控件持续消失后才记录成功。

停止扫描、用户导航、息屏、遮挡和屏幕配置变化都会清理倒计时证据。具备明确点击动作的目标继续沿用既有文案与广告证据校验。

## 回归方式

使用本地 Android 16 / API 36 模拟器，对照 3.1.2 Release 与 3.1.3 Release。独立模拟应用提供右下角、右上角、描述中拆分文案及每秒重建节点的触摸按钮；背景和按钮分别记录点击，探针核对 AdsBanner 的成功统计。

同时复用 3.1.2 的普通入口、说明文字、开关、引导页、广告设置、远处广告标记、返回循环、成功后再次返回及用户主动操作用例。补充静态倒计时、位置变化、倒计时增加、中部控件、大控件、冲突父节点、滚动容器与持续无效触摸控件。

3.1.2 与最终 3.1.3 分别通过 86 项模拟器断言：前者没有点击四类无点击动作的倒计时目标，后者均关闭一次、统计一次；普通页面反例没有误点。持续无效的目标仅收到一次手势，未计为成功。补充了即使暂时报告不可滚动，也按类型排除滚动与分页祖先容器的校验。189 项单元测试通过，Debug、Release 构建完成。

原始模拟页面、探针和对照结果保存于忽略目录 `app/build/ui-review/splash-313`，不随应用发布。本次结果覆盖模拟的无点击动作倒计时控件；尚未完成学习通当前版本的实体设备回归。
