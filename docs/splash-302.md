# 3.0.2：前置数字跳过按钮

掌盟反馈截图右上角显示“2 跳过”，前面还有独立广告标记。3.0.1 的数字前置匹配要求“秒 / s”，因此“2跳过”“2 跳过”都无法成为候选；只补文案匹配也不足以覆盖恢复检测，因为其广告证据判断同样遗漏了这种前置倒计时。

本轮分别补齐完整按钮匹配与倒计时证据，接受一至两位数字加“跳过”的无单位写法，兼容空格、换行和广告后缀。没有改变扫描频率、检测预算或点击位置规则，也不需要为掌盟手动添加规则。

“2 秒后可跳过”“第 2 步跳过”“2 跳过登录／教程／闹钟”等文案和单独数字不参与匹配。数字与跳过分开提供的旧路径也做了回归：同一控件的文字和描述、同一小型可点击父控件内的兄弟节点仍可组合，普通页面远处的数字不会被拼进跳过按钮。

## 对照范围

以发布版 3.0.1 安装包为基线，在同一专用 Android 16 模拟器中运行同形式布局。新写的两项回归测试先在原代码失败，再随修复通过。

| 场景 | 3.0.1 | 3.0.2 |
| --- | --- | --- |
| “2 跳过”及截图相近的右上角布局 | 漏跳 | 关闭 |
| “2跳过”“2 跳过广告” | 漏跳 | 关闭 |
| 仅响应触摸的前置数字按钮 | 漏跳 | 关闭 |
| 节点重建或按钮延迟出现 | 漏跳 | 关闭后只计一次 |
| 同包页面返回后出现“2 跳过”，无独立广告文字 | 漏跳 | 关闭 |
| 同控件文字“2”、描述“跳过” | 关闭 | 关闭 |
| 同一小型按钮内数字、跳过分成两个节点 | 关闭 | 关闭 |
| 普通页面的单独数字、步骤、登录及未来可跳过提示 | 不点击 | 不点击 |
| 恢复检测中只有“跳过”，旁边是无关数字 | 不点击 | 不点击 |

对照用例核对实际关闭、成功统计以及周围广告区域的点击次数；动作无效时不计数，控件替换时不提前计数。返回场景通过真实 Activity 打开和返回触发，不直接改写检测会话。
