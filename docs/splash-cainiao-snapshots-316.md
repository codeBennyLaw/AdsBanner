# 3.1.6 菜鸟原始节点快照复核

## 实机反馈所确认的阶段

用户安装前一轮 3.1.6（26）后，菜鸟仍然漏跳。其复制的本机诊断记录为「未找到可确认的开屏控件，未执行跳过」，动作 0 次；系统 API 37、实时通知已授权且通知总开关开启。本次菜鸟问题在识别阶段，不是成功跳过后的通知权限问题。先前的模拟结果不能证明已解决用户设备上的问题。

## 原始资料与旧规则错误

之前只读取了[上游菜鸟规则](https://github.com/ganlinte/GKD-subscription/blob/4746d192b4c57a4b62ed92a7f5deaf79e64fa811/src/apps/com.cainiao.wireless.ts)，其历史网页入口返回 404。本轮沿上游查看器源码找到了原始 GitHub 附件，并成功读取其中的 `snapshot.json` 和截图：

- [快照 19222366](https://github.com/user-attachments/files/19222366/file.zip)：菜鸟 8.10.305，屏幕 1080 × 2400。圆环为无文字、无描述的 `android.view.View`，边界 `(912,138)-(1032,258)`；同父容器末尾的空 `TextView` 在 `(60,1950)-(156,1992)`。
- [快照 21750819](https://github.com/user-attachments/files/21750819/file.zip)：菜鸟 8.10.805，屏幕 1440 × 3200。圆环边界 `(1244,176)-(1384,316)`；同父容器末尾的空 `TextView` 在 `(70,2619)-(182,2668)`。
- [快照 21913724](https://github.com/user-attachments/files/21913724/file.zip)：另一种拆分文字的控件，用于兼容复核。

两份圆环快照都使用完整第三方开屏容器与两层 `FrameLayout`，空标记节点却在左下角。前两轮人为要求标记位于右下角或占满整行，原始节点无法通过这个条件，漏跳可复现。截图中的像素位置不能直接作为无障碍节点边界的依据。

本次只在既有 SDK 结构路径中接纳左下角的小型空 `TextView`；完整容器、同窗口、相邻末尾节点、圆环尺寸、安全祖先和可见性检查仍参与核验。普通设置文案、错误容器、广告图片和屏幕中央的动作面不属于该结构。

这些是公开历史快照，不是从用户 API 37 设备读取的当前节点，也不代表菜鸟的最新版本。

## 结果确认的查询差异

将原始节点逐项回放为 Android 虚拟节点时，还发现“能遍历到完整容器，但资源 ID 查询返回空”的情况。圆环重建后，旧节点失效，原来的 ID 查询没有找到替代控件，广告未关闭却可能计为成功。

补查先按完整 ID 查询，返回空时在当前应用同一窗口内有界遍历，仍只接受相同的完整容器。该路径用于首页滚动后的专用容器查询和已提交动作的结果确认；圆环仍在时不计成功，也不再次触摸。

## 诊断操作

按用户要求将多余的「关闭」按钮替换为「复制」，保留「测试 / 复制 / 设置」。复制写入实际版本、全部最近检测及通知状态的完整报告，操作后弹窗继续显示；点击空白区域可关闭。长按文字选择仍可使用。

## 验证方法与边界

原始 JSON 直接作为回放输入，保留节点类名、文字、描述、点击能力、父子关系、子节点顺序和边界，不再用手写的右下标记结构替代。回放仅按模拟器显示尺寸缩放坐标；节点动作、触摸、延迟关闭、重建后未关闭、首页滚动和错误结构分别构造操作响应。

前一轮 3.1.6 候选包对两份原始圆环结构均未执行动作。本轮检查实际关闭、动作数、误点数、统计和合格实时提示；公开快照的回放仍然是模拟验证，用户当前菜鸟的实机结果需要另行确认。

原始附件、截图、JSON、回放源码及对照日志保存在忽略目录 `app/build/ui-review/cainiao-real-316`。


## 本轮结果

233 项单元测试通过，失败与错误为零。原始节点回放 15 个场景通过 70 项断言，前一轮菜鸟 45 个场景通过 203 项断言；一键复制、完整剪贴板内容、复制后弹窗保留、点击空白关闭和大字体操作区通过 12 项检查。合计 285 项模拟断言通过，未将历史 982 项报告当作本轮新结果重复计算。

原始结构的原生、触摸、延迟关闭和滚动后显示均实际关闭一次、动作一次、统计一次、发送一条合格实时提示。未关闭但圆环重建时只接受一次触摸，保持零成功统计；错误容器和不合法末尾标记没有动作，其他原始控件未误点。

一次既有兼容运行被另一个测试的安装过程打断，其记录保留为 `compatibility-45-interrupted.txt`，不纳入通过结果；随后串行重新完成整组。
