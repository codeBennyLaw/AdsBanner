# 3.1.6 菜鸟圆环开屏兼容修复

用户反馈安装 3.1.5 后，最新版菜鸟仍未跳过右上角圆环按钮。截图中的跳过文字和下方「AM广告」可能由广告 SDK 绘制，不能据此判断它们都有无障碍文字节点。本轮未连接用户设备，具体菜鸟版本号与实际节点结构尚未读取。

## 漏跳与误计数路径

3.1.5 对无文字圆环要求广告标记是同父容器中最后一个 `TextView`，并能读取独立的广告文字。这会漏掉标记不是最后一项、位于另一层容器，或 SDK 暴露空文字标记的形态。标记控件占满整行、文字靠右绘制时，节点边界也不等同于可见文字大小，原来的小型标记检查会拒绝它。

已核对的[公开菜鸟开屏规则源码](https://github.com/ganlinte/GKD-subscription/blob/4746d192b4c57a4b62ed92a7f5deaf79e64fa811/src/apps/com.cainiao.wireless.ts)使用圆环 `View` 与末尾 `TextView` 的结构关系，以及两层 `FrameLayout` 和完整开屏容器 ID；没有要求该 `TextView` 带有广告文字。源码中的历史节点快照链接目前返回 404，本轮未使用其原始节点作为设备证据。

此外，菜鸟首页先发出自动滚动事件、再显示开屏按钮时，原逻辑会结束本次扫描。结果确认还有一处问题：已经尝试点击的圆环重新创建、广告标记暂时消失，会被误当作目标消失，广告未关闭也计入统计并发送实时提示。

## 实现

- 实际广告标记在完整、同窗口的菜鸟第三方开屏容器内查找，不再要求同父节点、固定顺序或 `TextView` 类名。标记仍须具有独立广告文案、下方右侧的小型边界，以及安全的祖先层级；靠右绘制文字的宽行控件也可提供标记证据，行高仍严格限制，不能把整张广告图片当作标记。
- 空文字标记使用单独的 SDK 结构路径：小型无文字圆环 `View` 必须紧邻末尾空 `android.widget.TextView`，二者位于至少两层 `FrameLayout` 之内，最终归属完整的 `com.cainiao.wireless:id/fl_third_splash_container`。空标记也须满足下方可见短行边界，允许窄小右侧节点或接近全宽的短行；普通文字、错误层级和不相邻节点不构成证据。
- 菜鸟收到滚动事件后只保留该专用开屏容器的查询，不再查找普通页面的跳过文字、关闭图标或本地规则。点击和长按结束扫描；扫描仍受原启动预算限制。
- 已提交动作的结果确认在同一完整开屏容器中补查重建的圆环，不依赖广告标记仍有文字或仍可见。这个补查只判断目标是否仍存在，不授权新的点击；持续消失后才统计成功并发送实时提示。

## 验证设计

沿用 3.1.5 的模拟页面和通知探针，增加标记换序、跨容器、空文字 SDK 结构、整行标记、首页自动滚动和滚动后用户点击等场景。空标记另设缺少嵌套容器、插入普通节点、隐藏标记和设置文案负例；宽行标记另排除整张图片、大高度、半行和越界边界。

3.1.5 对七个新增漏跳复现均没有提交动作、没有统计或实时提示：标记换序、跨容器、空文字结构、两种自动滚动以及两种整行标记。修复包在这些场景中均实际关闭一次、尝试一次、统计一次、发送一条合格实时通知。广告标记隐藏后圆环重建但未关闭的复现，修复前错误统计一次并发送一条通知，修复后必须保持零成功记录。

模拟页暴露可读取的无障碍控件与容器。本次未增加屏幕图像识别；完全不暴露圆环及对应结构的渲染面不能仅凭截图中的坐标授权触摸。真实菜鸟效果仍需在用户设备安装候选包复测。
