# 与 2.2.0 的开屏兼容对照

3.0.0 将防误触条件加在了原有通用开屏路径上，造成可复现的漏跳：纯「跳过」必须有额外广告节点，顶部触控范围由屏高 25% 缩到 12%，带操作前缀的倒计时被拒绝，启动 3 秒后的 Activity 切换又可能将会话改成恢复检测。自绘文字的坐标兜底还会被大父容器否决。界面加载与转场没有参与这些判断。

## 修复边界

- 新启动沿用 2.2.0 的通用跳过思路：有效检测预算内，顶部等高置信位置不强制额外广告标记；其他紧凑按钮在前 6 秒兼容纯「跳过 / skip」。无需用户配置规则。只有同样文案的启动引导页也会沿用这一行为，无法仅凭完全相同的按钮区分二者。
- 普通关闭仍限启动最初 3 秒、右上位置和广告证据，并沿用容器应用禁用弱匹配的限制；「跳过登录 / 教程 / 验证」、闹钟、系统界面、小程序、锁屏、例外和功能关闭仍排除。没有恢复旧版包含「跳过」就接受的泛匹配。
- 启动阶段的 Activity / 临时窗口切换保留原起始时间与截止时间，不延长检测，也不延长弱匹配时限。真正亮屏或分享返回的恢复检测仍要求广告专属文案、倒计时或独立广告证据。
- 只给明确的顶部跳过控件恢复旧版较大的触控区域容差，不放宽一般关闭和整块广告容器。自绘控件只点击刷新后的小目标自身坐标，不向大祖先提交节点动作；遮挡仍禁止坐标操作。
- 控件替换和窗口切换不能直接视为关闭；出现消失迹象后刷新窗口缓存，持续确认至少 200ms。计数发生在确认之后，不影响首次点击的提交速度。未生效的动作继续不计数。

## 三版对照

独立 Android 16 / API 36 模拟器运行同一个模拟页，对比发布标签 `v2.2.0`、修复前 3.0.0（`3dde055`）和修复版。2.2.0 仅将本地诊断包的版本码对齐以覆盖安装，业务源码未改；各组均开启通用开屏并清空本地规则。实际点击由独立模拟应用记录，同时核对拦截统计和广告区域点击数。

| 模拟场景 | 2.2.0 | 修复前 3.0.0 | 修复版 |
| --- | --- | --- | --- |
| 顶部纯「跳过」，无广告文字节点 | 关闭 | 漏跳 | 关闭 |
| 「点击跳过 5s」 | 关闭 | 漏跳 | 关闭 |
| 顶部控件的触控高度为屏高 16% | 关闭 | 漏跳 | 关闭 |
| 启动 3.5 秒后进入同包开屏 Activity | 关闭 | 漏跳 | 关闭 |
| 中下部紧凑纯「跳过」 | 关闭 | 漏跳 | 关闭 |
| 大父容器下仅响应触摸的明确跳过文字 | 未关闭 | 未关闭 | 关闭 |
| 「跳过登录」 | 被点击 | 未点击 | 未点击 |

模拟页中的成功目标各关闭一次，未点击周围广告区域；修复版的成功统计也各增加一次。该表仅代表上述模拟布局，不能证明每个第三方应用版本都已适配；延迟采样包含模拟器窗口提交与调度，不作为真机速度承诺。

另外回归既有控件描述、拆分倒计时、不可文字查询的标记、动作无效、控件替换、通知栏、息屏和分享返回场景。原始源码、三版录屏及结果保存在忽略目录 `app/build/ui-review/splash-parity`；未操作实体手机。Debug、Release、140 项单元测试及 lint 通过。
