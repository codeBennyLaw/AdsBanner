# 亮屏与分享返回检测

## 回归原因

息屏会撤销扫描并清空开屏会话，但前台包名仍保留。此前只在包名改变时开始新检测，亮屏回到同一个应用就没有会话可恢复。同一应用内部的分享 Activity、分享 Dialog 返回也可能保持原包名，内容变化只能唤醒已有会话，不能补建检测。

## 恢复边界

- 息屏继续撤销扫描、手势回调、播放页和跳转守护任务。真实亮屏且解锁后，为实际前台、符合保护策略的应用补建一次检测窗口；亮屏缓存漏收解锁通知时仍可由原有状态门控恢复。
- 已声明 Activity 的切换、窗口重建、临时分享窗口返回，以及系统 Chooser / Resolver 返回可以触发短时复查。同包分享 Dialog 关闭后，即使原 Activity 不重建，也能由窗口变化确认返回。
- Activity 通过 PackageManager 核对，并使用最多 128 条缓存；普通 View/Dialog 类名不冒充 Activity 切换。临时窗口只在返回原应用的原窗口时恢复，不能把另一个前台窗口当成分享返回。
- 亮屏等待实际前台的请求有 15 秒期限，重复广播不延长期限。读取恢复窗口由事件触发，间隔至少 100ms；没有增加常驻恢复轮询。
- 同一个应用、Activity 和窗口的重复事件，以及普通内容更新，都不会重新开启已结束的检测。首次启动前三秒内的正常 Activity 跳转和临时窗口返回保留原有冷启动预算，不反复延长。

## 点击保护

恢复检测沿用用户配置的开屏检测时长、节点查询限频及整树预算，但只走通用强匹配：明确倒计时、广告专属文案或符合现有要求的独立广告证据。普通「关闭 / ×」和启动专用本地规则不在恢复窗口重新执行，避免误关正常页面或点击普通「继续」。正常新启动的行为保持原有规则。

锁屏、暂停、关闭功能、例外应用、系统界面及小程序的保护仍生效；通知栏保持展开，遮挡下不提交坐标手势。恢复扫描不会重置跳转守护的启动时间或清除用户主动分享、购物的意图。

## 回归方式

使用专用 AdsBanner_UI 模拟器（Android 16 / API 36），没有操作实体手机。独立模拟应用提供息屏后显示广告、同包分享 Activity、分享 Dialog，以及真实 Android ACTION_SEND Chooser 到本地模拟接收页的流程。最终分享回归将目标包限定为本地模拟应用，仅传递测试文字。

测试等待原检测窗口过期后再执行恢复动作，对比旧构建与修复包。另检查实际锁屏状态、重复窗口事件、无广告证据的引导页、普通关闭、启动专用本地规则、普通内容更新、冷启动、例外应用和功能关闭。成功时检查点击、统计和操作记录各一次。

旧包在亮屏、同包分享页面和分享面板返回三种场景都未点击；修复包完成一次点击和一次统计。完整录屏回归 46 项检查通过，130 项单元测试通过，debug、release 构建完成，lint 为 0 错误、169 项已有警告。

诊断源码、结果和原始录屏存放在本地忽略目录 `app/build/ui-review/splash-resume`，不随应用发布。结果覆盖这些模拟流程，尚未在用户当前安装的各应用版本上实测。

本轮进一步修复的按钮文案、节点查询及点击结果确认见[开屏漏跳回归修复](splash-reliability.md)。动作被接受或手势完成不再直接作为统计依据；测试中持续保留原按钮的模拟页不计为已关闭。
