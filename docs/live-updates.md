# 并行拦截实时通知

3.0.4 改善连续拦截时多条提示的独立展示。此前已使用不同通知 ID、保留最多 4 条，但未设置各自的分组，点击使用同一个 PendingIntent，诊断也只查看第一条。Android 16 模拟器中可复现 4 条通知被归入同一个系统聚合组，不能将这种表现解释成应用只发送了一条。

现在每条拦截都有独立的通知分组和点击标识，不创建合并摘要。支持实时通知的系统上，每条都独立请求提升，短摘要显示被拦截的应用名。早期 API 36 镜像可能缺少设置提升请求的便捷方法，使用公开的 `android.requestPromotedOngoing` 标记补齐。用户的通知和实时通知权限仍由系统执行。

同时最多保留 4 条提示；重复拦截同一个应用也各占一条。每条保持自己的开始时间和 10 秒期限，第 5 条只淘汰最早的一条。息屏停止应用内的周期刷新，通知的系统超时继续生效，亮屏后只恢复尚未结束的提示。

点击主页的实时通知说明可查看当前提示数量、已提升数量以及每条的状态。点击“测试”一次发送开屏、误触跳转和页面内广告三条示例，不增加拦截统计。大字体下缩短按钮文案并提供完整无障碍名称，详细内容可滚动查看。

## 验证与边界

在专用 Android 16 模拟器上使用正式版 3.0.3 做对照。旧版 4 条通知的分组均为空，被系统写入同一个聚合组，4 条也共用一个点击标识；修复版为 4 个独立分组和点击标识，没有系统聚合覆盖。每条均有独立提升请求，并通过系统的资格检查。

生命周期检查涵盖重复来源、持续刷新、超限淘汰、独立到期、息屏停止刷新、亮屏恢复、关闭开关、清理不影响其他通知，以及测试不增加统计。375dp 宽度下检查浅色、深色、大字体和关闭动画的诊断弹窗，并通过实际点击验证三条测试入口。

最终通过 53 项生命周期检查、浅色与深色大字体各 10 项界面检查，共 73 项模拟器检查。170 项单元测试通过，Debug、Release 已构建，lint 无错误、有 177 项警告。模拟器中安装的 Debug 文件与最终构建哈希一致。

该系统镜像没有授予提升权限，实际提升数为 0。上述结果证明多条独立通知、独立提升请求与资格成立，不能当作厂商灵动岛同时展示多条的真机证明。是否提升、状态栏和灵动岛同时展示多少条，仍由系统和厂商实现决定。[Android 官方说明](https://developer.android.com/develop/ui/views/notifications/live-update)也注明厂商可以增加提升条件。

原始驱动、模拟器录屏、截图和检查结果保存在忽略目录 `app/build/ui-review/live-304`。
