# 3.1.5 开屏统计与 LiveUpdate 遗漏修复

## 复现与原因

开屏统计、最近操作和拦截实时通知都由成功结果确认统一触发。动作返回成功或手势提交成功，本身不作为广告已经关闭的证明。

本轮在 3.1.4 Debug 对照包上构造 13 个原生和触摸场景，直接核对广告关闭、动作次数、统计和实际通知。原生及触摸动作之后，由旧页面报告自动滚动，再延迟关闭或进入主页的四个场景中，广告确实关闭，但统计增量和实时通知数量均为零。原生父容器回调与延迟关闭还出现了重复点击。

排查确认三个公共处理问题：

- 原生点击的起始时间在跨进程调用返回后才记录，而相关事件可能在调用返回前产生，导致事件时间早于记录时间，被当成其他用户操作。旧结果保留逻辑主要针对触摸点击，自动滚动也会结束并清除等待中的结果。
- 原生动作在 180ms 后就可能重试，早于部分控件实际关闭的时间。慢关闭期间反复点击可能继续推迟关闭；结果已被清除时，关闭之后无法记录统计或通知。
- 控件可以在 Activity 身份事件到达前被点击，结果记录的原始身份暂时为空。后续只比较该空快照，无法利用较晚到达的已核验窗口身份确认切页；旧窗口暂留系统列表也会阻止结果确认。

诊断日志中，开屏控件已经被提交原生点击，结果记录的 `activity` 仍为空；随后旧窗口被新主页替换，但等待结果最终被丢弃。调试用诊断字段已移除，不进入最终实现。

## 修复行为

- 提交原生点击之前记录动作起始时间。结果只在动作返回成功后建立，使用实际目标窗口的已核验身份，并补用较晚到达的原始窗口 Activity 信息。
- 提交之后 300ms 内、同窗口且关联目标的父容器点击或滚动事件结束扫描时，保留有限结果确认；来源不可读时仍必须满足时间和窗口约束。保留的结果不得再次提交触摸或重新授权扫描。
- 原生动作和触摸动作均给予 2 秒关闭确认期。确认原广告控件持续消失至少 200ms 后，统一记录一次开屏统计、最近操作并创建实时通知。
- 窗口过渡期间保留结果等待，核对实际前台、已核验页面身份和窗口层级。已核验新 Activity 的活动窗口完全覆盖旧窗口时，旧窗口仍被列出不再阻止确认；普通弹窗、局部覆盖和未知身份不能据此被当作广告关闭。
- 扫描结束后的状态栏控件仍按待确认目标所属应用核对，保留替代节点、遮挡与原控件检查。未关闭的控件和弹窗负例不记录成功，原生无效动作仍受有限重试约束。

## 验证记录

最终源码通过 224 项单元测试，失败与错误为零；Debug、Release 构建完成，版本为 3.1.5（25）。

15 个原生和触摸场景通过 88 项专项断言，覆盖正常关闭、父容器回调、自动滚动、跨进程回调延迟、切入主页、1.8 秒慢关闭、持续无效动作及弹窗。成功关闭的控件均关闭一次、统计一次、生成一条具备 Live Update 格式的实时通知；未关闭和弹窗场景没有计数或通知。原生无效动作可能按有限重试执行多次，成功控件及收到停止扫描事件的控件只执行一次。

独立跳转检查在关闭开屏跳过的条件下，确认实际返回来源应用、全局统计增加一次、目标应用的跳转统计保存值增加一次，并创建一条符合 Live Update 格式的通知。关闭实时提示时仍统计一次；例外目标、设置广告文字和滚动内容不触发返回或计数。

跳转模拟页在入场动画结束、节点稳定可见后报告内容就绪，再拉起目标应用；这避免首次检查落在动画中的越界节点上而没有形成广告上下文。原控件、设置和滚动负例及生产识别规则没有因此放宽。
