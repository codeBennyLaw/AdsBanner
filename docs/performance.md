# 3.0.0 性能优化记录

日期：2026-11-04。对比 3.0.0 初版 `cf6004b` 与本次优化后的 debug 构建。

## 改动

- 开屏查询与整树遍历分别调度。内容事件最短间隔 32ms 唤醒节点查询，完整遍历间隔至少 400ms；启动前 600ms 的无事件补查间隔为 80ms，随后按启动时长退至 120、240、600ms，检测总时限不延长。
- 本地规则仍优先，通过节点 ID 查询；未匹配或尚未适用的规则不强制触发整树遍历。通用顶部强匹配先做文字查询，右上角明确广告控件的触摸兜底也可复用候选，避免为了触摸再遍历整页。
- 窗口变化只标记缓存失效，在下一轮实际查询前统一清理；触摸提交前仍独立刷新窗口和遮挡信息。目标文案、位置、父容器、系统界面、例外应用和暂停状态的校验保留。
- 息屏取消开屏、播放页和跳转守护的等待任务；关闭对应功能立即撤销待处理检查。解锁不把旧页面重新当成应用启动。
- 多条拦截提示共用一条刷新回调。息屏停止进度刷新，系统超时移除机制保留；解锁按实际经过时间清理已到期提示。没有通知权限、通知被禁用或通道被关闭时，不创建提示计时任务。
- B 站无广告的播放器补查间隔由 500ms 调至 900ms；未发现播放器时逐步退至 900、1800、3000ms。交互与内容事件仍可提前唤醒，提示、面板、动作重试及结果确认保持原有快速检查。复用本轮活动根节点，补齐旧 Android 版本窗口对象的回收。
- 合并尚未执行的跳转前台窗口复查，新的窗口事件可将延迟检查提前，不重复排队，也不改变主动操作优先放行的判断。

## 模拟器对比

使用同一专用 `AdsBanner_UI` 模拟器、相同设置和独立模拟广告应用。没有操作实体手机。

无广告测试页包含 180 个普通内容节点和「跳过登录」，启动稳定 400ms 后，分别观察 10 秒。通过 `Debug.threadCpuTimeNanos()` 在 AdsBanner 主线程上采集时间差；外部页面的进程不计入该 CPU 时间。每个版本做两轮：

| 指标 | 初版 | 优化后 |
| --- | ---: | ---: |
| 第 1 轮主线程 CPU 时间 | 646.6ms | 240.4ms |
| 第 2 轮主线程 CPU 时间 | 458.1ms | 188.2ms |
| 两轮均值 | 552.4ms | 214.3ms |

广告测试页在启动后 500–1291ms 之间显示按钮，左右顶部各 4 次，记录「设置广告节点文字」到测试应用收到实际点击的单调时钟差：

| 指标 | 初版 | 优化后 |
| --- | ---: | ---: |
| 8 次延迟中位数 | 80ms | 50ms |
| 最小 / 最大 | 38 / 334ms | 30 / 159ms |
| 成功关闭 | 8 / 8 | 8 / 8 |

原始延迟（ms）初版为 `94, 334, 41, 242, 196, 66, 38, 52`，优化后为 `30, 159, 54, 40, 39, 119, 70, 46`。另外检查了息屏后的任务停止、通知原生到期、解锁不重扫、正常购物放行、精确规则与例外应用，以及模拟播放页的取消和关闭。

上述是小样本模拟器结果，用于确认工作量减少及响应路径改善；不是电池电流或整机功耗测量，也不能据此推算真机续航提升比例。静默页面的后期补查会更稀疏，实际广告若不提供内容变化事件，响应时间仍受补查间隔影响。

## 开屏按钮位置与留白布局回归修复

此前通用候选的位置打分只允许顶部，即使右下角的「跳过 3」文案符合强匹配，也会被直接排除；延长等待或添加轮询不能解决。只补底部 25% 仍会漏掉下方有留白、跳过按钮被顶到中部的广告。现在强匹配候选覆盖整个应用窗口：原有顶部、右下角优先，其他位置允许宽高不超过屏幕 32% 和 8% 的小型目标。仍需广告专属文案、明确倒计时或独立广告标记；通用「关闭 / ×」保持右上角限制。

快速文字查询、整树匹配、点击前刷新和触摸兜底使用同一位置策略。明确广告按钮可复用快速查询得到的候选完成触摸，不必等待下一轮整树遍历。新增区域中的普通「跳过 / skip」必须有同窗口、小尺寸、可见的独立「广告 / AD」等标记；标记也可位于中部。「广告设置」等普通文字不能授权新增区域的点击，弱匹配关闭按钮继续只接受顶部广告依据。窗口与遮挡检查、父节点尺寸限制及手势完成后计数保持生效，扫描时间和频率没有增加。

在同一专用模拟器上，清空本地规则和例外，模拟按钮在启动后 900ms 出现。旧构建对右下角「跳过 3」收到 0 次点击，修复后收到 1 次。一次完整录屏回归中，从设置按钮文字到测试页面收到点击的延迟为：明确倒计时 40ms，独立顶部广告标记加普通「跳过」280ms，触摸兜底 195ms。另一次倒计时测试为 116ms。这些是同类模拟布局的小样本，未验证用户截图中实际 B 站版本的节点结构，不能作为真机延迟承诺。

右下角专项 9 个场景的 27 项断言通过。补充留白布局录屏回归覆盖 14 个场景、42 项断言：中部右侧、中央和左侧倒计时跳过，中部独立广告标记及英文 AD 标记，触摸兜底，原有顶部和右下角；另检查无广告证据、顶部或中部「广告设置」文字、中部通用关闭、过宽按钮和全屏可点击父容器。拒绝场景保持 0 次点击，成功场景各增加 1 次统计和操作记录。零规则的新旧对比中，被留白顶至中部的按钮从 0 次点击恢复为 1 次；这一轮中部右侧、中央和左侧的响应分别为 49、241、61ms。几何单元测试另按左中右及不同高度组成网格，确认强匹配覆盖全屏，通用关闭保持右上角限制。
