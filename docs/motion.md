# 3.0.0 交互与开屏状态恢复

## 跟手返回

- 子页面直接使用系统返回进度，不再叠加一次缓出曲线。纵向拖动采用连续的阻尼限制，避免到边界时突然停止。
- 取消返回时，弹簧承接近期手势速度；回弹途中再次拖动从当前姿态继续。提交返回也从当前姿态接入返回入口的过渡。
- 父页面首个缓冲区尚未就绪时，短时重放它自己的显示列表，避免手势等窗口绘制。真实帧就绪后立即释放；承载视图预先挂载，手势期间切换可见性，不增删布局。
- 弹窗同样支持系统返回的开始、进度、取消及提交。收起时移动、裁切和淡出弹窗自身，入口按钮保持可见，不把弹窗缩成按钮。
- 弹窗返回期间复用已绘制内容，暂缓内部列表布局。单独记录根背景，避免隐藏原面板时 Android 清空背景显示列表、造成文字浮在下层页面上。
- 取消、关闭和生命周期结束时恢复裁切、轮廓及列表状态，释放临时绘制资源。系统关闭动画时跳过视觉变换；编辑器先由系统返回收起键盘，再关闭弹窗。

上述显示列表只重放应用自己的界面，不读取其他应用图像，也不保存截图。Android 29 以下弹窗使用原视图动画。

## 开屏失效修复

通用开屏识别在没有任何本地规则时也会执行。本地规则只是可选补充，管理页面已明确说明。

此前息屏缓存若没有收到后续解锁通知，可能一直阻止扫描。现在窗口变化会复查真实亮屏和锁屏状态；缓存为不可用时，内容事件也可触发复查，间隔至少 250ms。没有新增常驻定时轮询，锁屏仍禁止自动操作，解锁也不会把旧页面重新识别成一次应用启动。

诊断中把服务缓存设为息屏、保持模拟器实际解锁，并清空规则和例外：修复前模拟广告收到 0 次点击，修复后收到 1 次自动点击。

## 回归范围

使用专用 AdsBanner_UI 模拟器（Android 16 / API 36），未操作实体手机。诊断程序和录屏存放在本地忽略目录 `app/build/ui-review`，不随应用发布。

- 实际录屏覆盖统计、名单、拦截管理页面的左右返回、工具栏返回、取消与再次拖动，以及嵌套页面返回；逐帧检查录屏，没有发现整帧黑屏。
- 类型、排序和更新日志弹窗覆盖跟手取消、提交、入口按钮持续可见及无重放按压；对浅色弹窗的实际像素另外检查背景，旧构建可复现背景丢失。
- 编辑器检查真实软键盘的两次返回；关闭系统动画后再次检查页面和弹窗返回。
- 320dp 宽度、1.6 倍字体、深色模式覆盖管理、编辑、导入导出及列表回归。核心检查覆盖自动跳过、误拦截保护、规则与例外、通知栏展开和息屏任务撤销。

同一模拟器空闲时顺序采集页面返回的 FrameMetrics，小样本对比如下（不含各窗口首帧）：

| 指标 | 改动前（211 帧） | 改动后（219 帧） |
| --- | ---: | ---: |
| 总耗时中位数 | 29.47ms | 29.92ms |
| 总耗时 P95 | 77.14ms | 67.44ms |
| GPU 耗时中位数 | 14.46ms | 11.48ms |
| GPU 耗时 P95 | 27.49ms | 22.92ms |

该样本中 GPU 与尾部耗时下降，总耗时中位数没有改善。模拟器数据不能推断真机帧率或续航；旧 Android 弹窗回退路径尚未在对应系统上实测。
