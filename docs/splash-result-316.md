# 3.1.6 延后滚动导致的开屏结果遗漏

## 用户反馈与版本

用户确认反馈来自 3.1.5 正式版：有时没有跳过，有时已自动回到应用主页，却没有增加开屏统计或触发 LiveUpdate。3.1.6 的候选修改位于 PR #26，尚未合并或发布；不能把 3.1.5 的实际反馈当作用户已经验证了这些修改。

## 新增复现

构造原生与触摸动作已接受、750ms 后由原控件的布局父容器报告滚动、1250ms 后才关闭广告的页面。3.1.5 对照中，广告关闭一次、执行一次，但统计增量和拦截提示数量均为零。

原结果保留逻辑只接纳动作后 300ms 内的相关报告。较晚的布局滚动会结束扫描；当时控件还在，既不能证明已关闭，又无法保留既有动作的结果，等待记录被清除。之后真正关闭时，统计和实时提示的公共入口不再执行。

## 处理与边界

同一目标窗口、来源与原控件相关的滚动报告，可以在原有 2 秒结果期限内保留结果确认。保留时结束扫描并禁止后续触摸，不重新开始计时，也不延长原启动预算。点击、长按、其他窗口和不相关来源不使用这条晚滚动路径。

结果仍要求原控件持续消失；接受动作不等于已跳过。广告未关闭、普通弹窗遮挡、倒计时归零但目标仍在的页面不计成功。真实用户操作中断的等待不会在之后自动补计。

## 定位实际设备的失败阶段

主页「拦截实时提示」的诊断面板同时显示实际安装版本和最近 8 条开屏检测结果，区分：

- 没有找到可确认的控件，或候选未通过动作条件。
- 已提交动作但未能确认关闭，因此尚未计入统计。
- 已确认关闭并保存统计，以及通知实际发送、应用开关关闭、权限不足、系统或渠道关闭、发送失败等状态。

记录只包含应用包名、时间、处理阶段、提交动作次数与通知发送结果，保存在本机，不保存截图、页面文字和无障碍树。重新启动后，未结束的旧记录标记为中断，不显示为仍在等待。诊断内容可以选择复制，报告区限制高度并滚动，大字体下为操作按钮留出空间。

通知发送与系统提升资格分别显示：成功提交通知并不代表系统必然把它展示为 LiveUpdate。关闭实时提示仍保留成功统计。

## 验证来源

忽略目录 `app/build/ui-review/result-316` 保存新增页面、探针和对照记录。`baseline-native-late-report.txt` 是 3.1.5 成功关闭但漏统计的失败证据；`fixed-all.txt` 逐场景核对实际关闭、尝试、背景误点、统计、通知与诊断存储。

新增复现不是用户设备的实际节点树。本轮仍未连接用户设备，真实菜鸟和厂商系统行为需安装本次候选包复测。


## 本轮结果

232 项单元测试通过，失败与错误为零；Debug、Release 构建、版本 3.1.6（26）与签名检查通过。

结果与诊断专项 25 个场景通过 260 项断言。原生和触摸动作后较晚的关联滚动，同窗口关闭和切到主页均关闭一次、统计一次、发送一条合格实时提示。未关闭、弹窗、归零后仍在的目标不计成功；后续普通点击结束等待，关闭提示开关时仍统计且不发送通知。诊断中的动作次数、应用身份、完成状态与实际通知结果逐项对照。

菜鸟 45 个场景通过 203 项断言。其余 8 组回归通过 513 项断言，通用、哔哩哔哩与学习通、既有结果确认的 62 个场景稳定字段与 3.1.5 一致。

诊断面板在 1.5 倍字体下通过 6 项独立检查：版本、持久化阶段、文字选择复制，以及测试、设置、关闭按钮均可操作。合计 982 项模拟断言通过，不把最终包复测的重复场景再次相加。

完整回归后仅收尾调整手势被系统接受时的诊断计数和报告滚动布局，未改变自动操作与结果确认条件。最终包复测原生、触摸、未关闭和提示关闭场景及大字体诊断操作区；分阶段源码和安装包校验值记录在 `artifact-verification.json` 与 `verification.json`。
