# 哔哩哔哩暂停广告适配

这是内置的页面内广告清理能力，开启对应开关即可使用，不需要配置本地开屏规则。沿用无障碍节点操作，没有增加网络代理、证书安装、截图或图片识别。

## 匹配与点击

- 在半屏播放器中，关联「后将展示广告」等明确提示与同一提示行右侧的「取消」。允许全宽、不可见的 Compose 包装节点，以及直接挂在播放器下的兄弟控件；可见性、尺寸、相邻位置和共同作用范围仍需满足。
- 关闭广告不再强制要求 `fl_tab_pager_container`。先确定关闭图标所属的最近一块面板，再检查这块面板内的广告依据，不能为了寻找广告标记一路扩大到整页。
- 支持 `关闭暂停页`、`关闭暂停广告`。部分版本没有广告标记时，要求专属关闭语义与同父级原生 Button 同时存在，并满足播放器下方、面板右上角及小尺寸约束。普通 `close / × / 关闭` 在新容器下仍需同面板广告标记，单独「查看详情」不授权关闭。
- 下方独立推荐卡片的广告标记不能授权上方其他关闭按钮。带有「更多」或其他可点击控件的父容器不借作点击目标，避免点到广告菜单或广告内容。
- 可点击节点优先使用原生动作，平移时核对控件身份、尺寸及父子相对位置，不固定等待另一帧；同一节点复用刚刷新的结果，避免再次刷新时跨帧产生位置矛盾。
- 坐标兜底必须连续两次观察到关闭控件位置稳定；发送前重新核对实际活动窗口及点击点上方的通知栏、键盘等窗口。等待稳定不会消耗三次重试额度。

## 结果确认与生命周期

每次广告的取消、关闭分别最多尝试三次，仍保留重试间隔。取消被接受后广告仍弹出，可以继续关闭，最终只计一次。

原生动作返回成功或手势完成并不立即计数。取消需要等原提示展示窗口过去，关闭需要连续观察到广告消失；已知面板内的广告文字、原生 Button 或大幅广告图片仍在时，不因关闭图标先隐藏而提前确认。

系统窗口成为活动窗口时撤销扫描和未完成动作，不收起通知栏；即使系统仍把 B 站标为活动窗口，坐标点击也必须通过点击点遮挡检查。已观察到的 B 站页面可由后续窗口变化恢复检查，解决收起通知栏后静止页面不再产生内容事件的问题；离开 B 站、关闭功能、加入例外或息屏仍停止任务，没有增加常驻轮询。

## 本地回归

使用专用 AdsBanner_UI 模拟器（Android 16 / API 36）及独立模拟页面，没有操作实体手机。诊断程序和原始录屏位于忽略目录 `app/build/ui-review/bili-v3`，不随应用发布。

完整录屏回归的 49 项检查及补充安全回归的 15 项检查通过。debug、release 构建完成，123 项单元测试通过；lint 为 0 错误、169 项已有警告。

- 新旧对比：全宽提示栏、播放器直属提示、新关闭文案及更换面板容器四种场景，旧构建均未点击，修复后均完成一次动作和一次确认统计。
- 完整录屏检查覆盖原有取消与关闭、无广告标记的专属关闭结构、移动中的节点和触摸兜底、普通弹窗、独立推荐广告、推荐首页、取消后继续弹广告、无效点击的有限重试、只隐藏控件仍保留广告图片、通知栏遮挡及收起恢复、例外应用。
- 补充检查在新容器中单独「查看详情」不会触发普通关闭，并复查新容器、专属关闭及两种移动控件。单元测试覆盖包装层、跨面板误配、父容器含菜单、残留内容和手势稳定前不消耗重试。

这些结果只证明已覆盖的节点结构与保护路径。尚未在用户当前安装的 B 站版本上实测，也不代表支持横屏全屏播放器、所有灰度布局或没有可访问节点的广告。
