# 3.1.5 菜鸟圆环开屏按钮漏跳修复

## 截图与原因

用户提供的菜鸟开屏截图中，右上角是带进度圆环的「跳过」，没有数字倒计时；「AM广告」位于广告图片右下角，底部还有菜鸟标识与「摇一摇」入口。

通用规则不能仅凭「跳过」授权点击。菜鸟专用的第三方开屏容器之前没有作为证据，底部标记也不满足相近位置的通用广告标记条件；文字绘制在 Canvas 上的版本还可能没有可查询的文字或描述。

公开[菜鸟规则](https://github.com/ganlinte/GKD-subscription/blob/4746d192b4c57a4b62ed92a7f5deaf79e64fa811/src/apps/com.cainiao.wireless.ts)记录包名 `com.cainiao.wireless` 和完整容器 ID `com.cainiao.wireless:id/fl_third_splash_container`，并同时覆盖文字按钮与 `View`、末尾 `TextView` 的组合结构。[另一份菜鸟规则](https://github.com/Lin-arm/GKD_subscription/blob/7014842c34c226a4cfd9e6d55f98f92813326ebe/src/apps/com.cainiao.wireless.ts)用于核对应用包名和页面信息。

没有连接用户设备，截图不包含节点 ID、层级和动作信息；以上是依据截图与公开结构构造的可复现路径，并非读取了当前菜鸟 APK 的实际节点。

## 修复范围

- 仅在菜鸟包内，将完整且覆盖主要窗口区域的专用第三方开屏容器作为证据，处理其中右上角小型「跳过」或 `Skip`。目标和容器分别核对边界、尺寸、同窗口与包含关系，不依赖 Activity 身份事件先于按钮出现。
- 无文字、无描述的 `View` 还须具有足够大的圆环尺寸、近似圆形比例和符合截图的上方位置；同父容器的末尾 `TextView` 须是可见且位于下方右侧的独立「AM广告」或广告标记。共享父容器中的其他广告控件可以位于二者之间。
- 目标全部祖先须属于同一应用窗口，排除设置、搜索、输入、开关和滚动容器。上方小蓝点、图片、中心「摇一摇」、大容器和普通引导页不作为无文字跳过目标。
- 原生节点动作优先；不能执行节点动作时，只在当前窗口、尺寸、证据和遮挡再次通过检查后触摸目标自身中心，避开入场动画。同一已核验容器窗口仅接受一次触摸，不因圆环节点重建或移动重置机会。
- 已接受动作的结果沿用 3.1.5 的确认流程。只对已核验的菜鸟容器控件补查替代节点，避免圆环刷新被误当成关闭；持续消失后才记录统计、最近操作并创建实时通知。
- 原控件仍是同一节点时，移动本身不被当作控件消失；替代节点限定在已核验容器内，重新核对文字或圆环尺寸，避免将小蓝点等其他无文字节点当成替代圆环。

## 验证方法

使用菜鸟包名和资源 ID 构造带文字、仅描述、Canvas 绘制、原生动作、纯触摸、延迟关闭及节点重建的控件；广告详情、摇一摇和小蓝点分别计入误触记录。另构造相同外观的其他包、错误或小型容器、隐藏与错误广告标记、不同窗口、设置、滚动、开关、大控件、中心位置、用户操作、返回以及通知栏遮挡场景。

原有 3.1.5 Debug 对六种目标形态均未执行动作；新包的无文字圆环专项已验证原生与触摸路径，以及控件重建和移动后的单次触摸与成功确认。
