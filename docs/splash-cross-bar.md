# 3.0.1：状态栏与叉号开屏按钮

本轮以 3.0.1 分支上一轮构建（`cfe3d95`，尚未发布）为基线，补充状态栏区域和纯叉号关闭按钮的识别。

## 应用自己的状态栏区域按钮

原来会拒绝可见性标记为假的节点，坐标触摸也会被上层状态栏挡住。部分广告控件位于应用延伸到状态栏的区域，虽然仍支持无障碍点击，却因此被漏掉。

现在核对节点所属应用、应用窗口、上层系统窗口及真实重叠范围：确实位于薄状态栏下方的应用控件，可执行节点动作；不向该区域发送坐标触摸。系统状态栏和通知本身不作为广告按钮。较大的通知栏、浮层不通过薄状态栏例外。

关闭确认也识别这类被遮住但仍存在的节点。动作被接受、可见性为假都不代表广告已经消失；持续无效的目标有限重试，不计数。

## 只有“×”或图片关闭图标

- 叉号需在同应用、同窗口中找到独立的广告标记，位置处于相近的顶部带；“广告设置”等普通文字、背景远处的广告，以及别的窗口中的广告不作为依据。
- 小型左上角叉号和启动预算内延迟出现的叉号可参与匹配，不再一律受前 3 秒、60 个节点的限制；完整遍历仍限制在 700 个节点、30 层内。
- 没有文字或描述时，只有同时含广告／开屏与关闭动作词的完整资源 ID 才可成为叉号候选，再检查广告证据、尺寸、位置和窗口。普通 `toolbar_close`、`dialog_close` 不参与这种推断，有冲突文字的控件也不会被覆盖。
- 内容区目标确实只能响应触摸时，使用刷新后的小目标自身坐标，不向大型父容器提交动作。状态栏区域仍只执行节点动作。
- 原控件被同 ID 的新图标替换时继续确认当前目标，避免将节点重建当成关闭成功。
- 用户点击、长按或滚动后结束本轮叉号自动关闭；通过当前待确认目标区分引擎自己的点击事件，使未生效动作仍可有限重试。

普通“关闭”按钮继续使用原来的启动初期规则。亮屏、分享返回的恢复检测不启用这条通用叉号路径。

## 录屏对照

| 场景 | 本轮之前 | 修复版 |
| --- | --- | --- |
| 3.8 秒后出现的叉号 | 漏跳 | 关闭 |
| 超过 60 个节点的广告页 | 漏跳 | 关闭 |
| 左上角叉号 | 漏跳 | 关闭 |
| 无文字、具有明确广告关闭 ID 的图标 | 漏跳 | 关闭 |
| 状态栏内、可见性为假的应用按钮 | 漏跳 | 节点关闭，无坐标触摸 |
| 内容区仅响应触摸的叉号、图片按钮 | 漏跳 | 点击自身位置关闭 |
| 图标替换后才真正关闭 | 漏跳 | 真实关闭后只计一次 |
| “广告设置”旁的普通叉号 | 被点击 | 不点击 |
| 用户主动进入普通页面后的叉号 | 被点击 | 不点击 |

专用 Android 16 模拟器实际核对了节点归属、应用窗口与更高层系统状态栏的物理重叠；状态栏用例不是仅将按钮放在页面顶部。基线和修复版使用同一模拟应用。成功用例记录真实关闭一次、统计增加一次；周围广告区域点击为零。状态栏所有用例坐标触摸为零，持续无效的隐藏目标只执行三轮节点动作，不误计数。

另检查了闹钟处理应用、没有广告标记、普通资源 ID、冲突文字、不同窗口和展开通知栏等反例。通知栏保持展开，收起由测试驱动模拟用户操作，应用没有自行收起通知栏。

本轮 74 项检查通过，并重跑上一轮 171 项开屏、动作确认、通知栏、亮屏与分享恢复检查，共 245 项。163 项单元测试通过，Debug、Release 已构建，lint 无错误，报告有 177 项警告。

原始录屏、模拟页、测试驱动和结果位于本地忽略目录 `app/build/ui-review/splash-cross-bar`。没有操作实体手机。完全不暴露文字、描述或明确关闭 ID 的图片不能靠这些规则识别，未引入截图识别或固定坐标盲点；上述模拟结果也不代表全部第三方应用版本已经适配。
