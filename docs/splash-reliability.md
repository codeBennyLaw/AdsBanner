# 开屏漏跳回归修复

本轮用旧构建和修复包对比了通用开屏场景，测试时清空补充规则。修复涉及识别、启动窗口和动作结果，界面加载动画不参与无障碍扫描。

- 同一按钮的文字与无障碍描述可分别提供「跳过」和倒计时；同一个小型可点击控件内的拆分文字也可以组合。独立页面里的普通计时器不能充当跳过按钮的证据。
- 应用启动前三秒内出现、撤下临时窗口时，保留原有冷启动检测。不会重置起始时间或延长弱匹配预算，避免被提前改成只允许强匹配的返回检测。
- 已经通过节点树找到广告证据的候选，允许有界地重新读取节点树确认标记。文字查询接口不支持该标记时，不再否决可访问的真实广告节点。普通快速查询不会因此每次都遍历整树。
- 节点动作或触摸回调完成后，连续复核原控件消失或不再是跳过控件后才记录拦截；同应用窗口切换期间保留短时结果确认。倒计时控件被替换时先找同一位置的新节点；按钮暂时禁用时继续短时确认。动作被接受但没有生效时，在重新校验目标、前台和遮挡后做一次触摸兜底；同一未变化的失败目标不会被持续点击。
- 小型跳过控件自身声明点击动作时，大广告祖先不再否决它自己的触摸位置；大祖先本身仍不能被点击。不具备独立点击动作、只挂在大广告容器下的文字继续排除。
- 完整扫描在 700 个节点、30 层处停止向下读取。旧系统触摸新鲜度以本次目标校验为准，每次手势使用独立代号，过期回调不能结束后续手势。

普通引导页的「跳过」、无广告证据的通用关闭、大广告容器、锁屏、例外应用和功能关闭仍保留原有保护。通知栏不自动收起，遮挡时不发坐标手势；系统完全隐藏底层节点时只能等待其重新可访问，不能据此记录关闭成功。

独立 Android 16 / API 36 模拟器覆盖了按钮描述、同控件拆分倒计时、动作无效、拒绝节点动作、按钮暂时禁用、延迟关闭、节点替换、启动弹窗和不可文字查询的广告标记，并回归亮屏、分享返回、普通引导、底部跳过和保护开关。通知栏测试中，系统完全隐藏了底层应用节点：保持展开期间不盲点、不误记，用户收起后继续完成关闭。未操作实体手机，不能据此保证所有第三方应用版本都能跳过。诊断源码、原始录屏和结果在忽略目录 `app/build/ui-review/skip-regression`。
